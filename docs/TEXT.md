# Форматирование текста тегами

Текст печатается как поток ESC/POS-команд. Теги в квадратных скобках
выполняются **последовательно**, как вызовы методов Adafruit_Thermal.
Закрывающие теги не нужны: тег действует до следующего тега.

Теги работают **в файлах `.txt`** и в поле «Текст» в режиме «Текст с
форматированием» (а также через API). Файлы `.md`, `.csv`, `.log` и режим
«Текст без форматирования» печатаются как есть, без разбора тегов.

## Синтаксис

- `[команда]` — без аргументов, например `[boldOn]`.
- `[команда,аргумент]` — например `[setSize,L]`.
- `[команда,арг1,арг2,...]` — например `[setHeatConfig,11,120,40]`.
- Регистр команд не важен: `[boldOn]` = `[boldon]`.
- Неизвестный тег печатается как обычный текст.
- Чтобы напечатать литерал `[`, используйте `[[`.

Пример:

```text
[setSize,L]ЗАГОЛОВОК
[setSize,M]Обычный текст, [boldOn]жирное слово[boldOff] и [underlineOn]подчёркнутое[underlineOff].
[justify,R]Итого: 1000 ₽
[justify,L][inverseOn]Инверсия[inverseOff]
```

В конце автоматически добавляется перевод строки, если текст не
заканчивается на `\n`; затем выполняется финальная подача (`feed` из API
или `[feed,N]`).

## Форматирование

| Тег | Действие |
|---|---|
| `[setSize,S]` | обычный размер |
| `[setSize,M]` | двойная высота |
| `[setSize,L]` | двойная ширина и высота |
| `[setFont,A]`, `[setFont,B]` | шрифт A или B |
| `[justify,L]`, `[justify,C]`, `[justify,R]` | выравнивание |
| `[boldOn]`, `[boldOff]` | жирный |
| `[underlineOn]`, `[underlineOn,2]`, `[underlineOff]` | подчёркивание 1/2 px |
| `[inverseOn]`, `[inverseOff]` | инверсия |
| `[doubleWidthOn]`, `[doubleWidthOff]` | двойная ширина отдельно |
| `[doubleHeightOn]`, `[doubleHeightOff]` | двойная высота отдельно |
| `[strikeOn]`, `[strikeOff]` | зачёркивание |
| `[upsideDownOn]`, `[upsideDownOff]` | перевёрнутый текст |
| `[setLineHeight,24..255]` | межстрочный интервал в точках (по умолчанию 30) |
| `[setCharSpacing,0..255]` | дополнительный интервал между символами |
| `[tab]` | табуляция |
| `[feed,0..255]` | подача строк |
| `[feedRows,0..255]` | подача в точках |
| `[setDefault]` | сброс форматирования (кодовую страницу не меняет) |
| `[reset]` | полный сброс задания, возврат к кодовой странице из настроек |

## Кодировка

| Тег | Действие |
|---|---|
| `[setCodePage,6]` | CP1251 (по умолчанию, если так задано в настройках) |
| `[setCodePage,7]` | CP866 |
| `[setCharset,0..15]` | таблица символов ESC/POS |

`[setCharset]` меняет таблицу символов принтера, но не конвертацию
текста в прошивке. Для кириллицы используйте `[setCodePage,6|7]`
(нумерация Adafruit/Epson; 46 — Hebrew, 17 — Greek, это не кириллица).

По умолчанию используется страница из настроек (`POST /api/config`,
поле `codePage`). Если кириллица печатается «кракозябрами» — проверьте
страницу тестом `POST /api/test/codepage`.

Кириллица корректно конвертируется для CP1251 и CP866. Для других
кодовых страниц прошивка передаёт только ASCII, остальное заменяет на
`?`. Символ `₽` в CP1251/CP866 отсутствует — печатается как `руб.`

`[setDefault]` не меняет кодовую страницу (как в Adafruit_Thermal).
`[reset]` сбрасывает задание и возвращает кодовую страницу из настроек.

## Дополнительно

| Тег | Действие |
|---|---|
| `[setBarcodeHeight,1..255]` | высота последующих штрихкодов |
| `[qr,URL]` | вставить QR с данными (модуль 2–4 автоматически, до 690 байт) |
| `[image,photo.bin]` | вставить `.bin`/`.raw` с SD в поток текста |
| `[setPrintDensity,0..31,0..7]` | плотность и пауза (`DC2 #`) |
| `[setHeatConfig,dots,time,interval]` | параметры нагрева (`ESC 7`) |
| `[sleepAfter,N]` | сон через N секунд |
| `[sleep]`, `[wake]` | сон/пробуждение (`[wake]` — `ESC @`: выводит из сна и сбрасывает форматирование) |
| `[online]`, `[offline]` | перевод принтера online/offline |

Эти команды меняют состояние принтера, а не только текст. `[offline]`
останавливает печать до `[online]`; `[sleep]` может усыпить принтер
посреди задания.

## Что не является тегами

Штрихкоды, тестовая страница и проверка бумаги — отдельные вкладки и
API-эндпоинты:

- `POST /api/barcode`;
- `POST /api/test`;
- `GET /api/printer/status`.

QR и изображения можно вставлять тегами `[qr,...]` и `[image,...]`;
отдельные API `/api/qr`, `/api/bitmap` тоже остаются.

## API

Теги работают в `POST /api/text` (JSON и plain text),
`GET /api/print?text=...` и `POST /api/sd/print` для файлов `.txt` на
SD. Для `.md`, `.csv`, `.log` теги не разбираются — они печатаются как
обычный текст. В JSON можно явно отключить разбор: `"plain": true`.

Поля `size`, `align`, `bold`, `underline` в JSON остаются для
совместимости и задают **начальное** форматирование перед разбором
тегов. Если они не заданы, начало — S/слева/без жирного/без
подчёркивания.

```json
{
  "text": "[setSize,L]ЗАГОЛОВОК\n[setSize,S]Обычный текст",
  "feed": 2
}
```

## Текстовые файлы на SD

Отдельных шаблонов нет. На SD лежат обычные файлы в UTF-8:

- `.txt` — наш формат с тегами; теги выполняются при печати;
- `.md`, `.markdown`, `.csv`, `.log` — обычный текст; теги и Markdown не
  разбираются;
- `.bin`, `.raw` — готовые 1-битные изображения;
- `.png`, `.jpg`, `.jpeg`, `.gif`, `.bmp`, `.webp` — исходные картинки,
  хранятся как есть и конвертируются в `.bin` уже во вкладке «Фото»;
- `.prn` — сырой ESC/POS.

Текстовые файлы читаются потоково, лимит — 64 КБ.

Загрузить и напечатать файл можно во вкладке «SD-карта» или через API
`POST /api/sd/upload` и `POST /api/sd/print`.

В веб-интерфейсе кнопка «Открыть» у файла не печатает его сразу, а
переносит содержимое в подходящую вкладку. У текстовых файлов также есть
«Просмотр» — быстрый показ содержимого без загрузки в редактор.

- `.txt` → «Текст», формат «Текст с форматированием»;
- `.csv`/`.log` → «Текст», формат «Текст без форматирования»;
- `.md`/`.markdown` → «Текст», формат «Markdown», документ сразу
  конвертируется;
- `.bin`/`.raw` → «Фото», изображение готово к печати; яркость, контраст
  и инверсия применяются повторно (файл уже 1-битный, дизеринг не
  восстановит полутона);
- `.png`/`.jpg`/… → «Фото» как исходник: настройки применяются полностью,
  «Сохранить на SD» кладёт рядом готовый `.bin`;
- `.prn` → hex-просмотр в «SD-карта» и отдельная кнопка «Печать .prn».

В поле «Текст» формат выбирается списком «Формат»:

- **Текст с форматированием** — теги ESC/POS, ниже показывается панель тегов;
- **Markdown** — исходник Markdown, кнопка «Конвертировать и просмотреть»,
  предпросмотр и печать уже готовых тегов;
- **Текст без форматирования** — печать как есть, квадратные скобки не
  разбираются.

Правки в «Тексте» отправляются через `/api/text` и на SD не сохраняются:
после редактирования файл на карте остаётся прежним.

## Markdown

Markdown **не разбирается на ESP32**, конвертация идёт в браузере. В поле
«Текст» выберите формат «Markdown», откройте `.md` из раздела «SD-карта»
(кнопка «Открыть») или вставьте текст вручную, затем нажмите
«Конвертировать и просмотреть». Документ превращается в текст с
нашими тегами, картинки скачиваются и конвертируются в `.bin`. Результат
можно напечатать сразу, сохранить как `.txt` на SD или перенести в режим
«Текст с форматированием» кнопкой «В текст с тегами».

## Ограничения

- Текст в `/api/text` — до 4096 байт (включая теги).
- Текстовый файл на SD — до 64 КБ.
- JSON-тело до 16 КБ.
- Теги не вкладываются и не закрываются: важен порядок.
- Панель кнопок в веб-интерфейсе вставляет тег в позицию курсора;
  выделенный текст не оборачивается автоматически.
