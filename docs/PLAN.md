# План развития: Wi-Fi принтер с API и веб-интерфейсом

## 1. Решение

Выбран один маршрут: **ESP32 подключается к существующей Wi-Fi-сети** и
становится сетевым принтером. Любое устройство в сети — Android, Windows,
Linux, планшет, скрипт — печатает через браузер или HTTP API. USB, Bluetooth
и автономный режим Uno + SD в текущую архитектуру не входят.

Это даёт максимум возможностей при минимуме сущностей:

- не нужно ставить приложение на каждое устройство;
- не нужно спаривать Bluetooth и держать телефон рядом;
- один веб-интерфейс для всех;
- API позволяет интегрировать печать куда угодно;
- обновление прошивки по Wi-Fi (OTA).

## 2. Архитектура

```
┌─────────────┐   Wi-Fi   ┌──────────────────────────┐   UART 9600   ┌────────────┐
│ Android     │◄─────────►│ ESP32-WROOM-32           │◄─────────────►│ T7-US      │
│ Windows     │  HTTP :80 │  • Wi-Fi STA             │  TX/RX/DTR    │ 58 мм      │
│ Linux/скрипт│  mDNS     │  • WebServer + API       │  5 В TTL      │ ESC/POS    │
└─────────────┘           │  • OTA                   │               └────────────┘
                          │  • NVS (настройки)       │
                          │  • SD (SPI)              │
                          └──────────────────────────┘
                                     │
                          12 В 2 А → MP1584 → 7,4 В → J1
                          SD-карта: SPI, FAT32, 4–32 ГБ
```

- Питание принтера — отдельно от ESP32, общий GND.
- Линии TX/DTR принтера согласуются до 3,3 В (делитель или TXS0108E).
- Принтер работает на 9600 бод; DTR используется как аппаратный flow control.

## 3. Что реализовано (v1)

Прошивка собирается (`pio run -e esp32dev`) и включает:

- подключение к Wi-Fi через WiFiManager (точка `Thermal58-setup`, пароль
  `thermal58`, настройки в NVS);
- mDNS `thermal.local`;
- веб-интерфейс: текст, фото, QR/штрихкод, настройки, API;
- REST API с CORS;
- потоковую загрузку изображений (multipart, без буферизации всего файла
  в RAM);
- ESC/POS: текст CP1251/CP866, размер, жирный, подчёркивание, инверсия,
  выравнивание, межстрочный/межсимвольный интервал, шрифт A/B,
  strike/upside-down, подача, QR, штрихкоды;
- **разметка текста тегами** в стиле Adafruit_Thermal (`[setSize,L]`,
  `[boldOn]`, `[justify,R]`, ...) с панелью кнопок и справкой;
- настройку плотности (heat time) с сохранением в NVS;
- опрос статуса принтера (`DLE EOT`);
- **SD-карту:** список файлов, загрузка изображений `.bin`/`.raw`,
  сырого ESC/POS `.prn` и текста `.txt`/`.md`/`.csv`/`.log`,
  предпросмотр изображений и текста, печать с карты без загрузки в RAM,
  скачивание и удаление, переподключение карты;
- **Markdown в браузере:** конвертация `.md` в `.txt` с тегами,
  скачивание и конвертация картинок, предпросмотр и сохранение на SD или
  в поле «Текст»;
- OTA `ArduinoOTA` и профиль `esp32dev_ota`;
- светодиод состояния.

Что ещё не проверено на реальном железе:

- полярность и работа DTR на конкретной плате;
- реальная скорость/стабильность 9600 при печати фото;
- кодировка: страница 6 (WPC1251) проверена оригинальным скетчем на
  Adafruit_Thermal; переключается настройкой `codePage` или тегом
  `[setCodePage,6|7]`;
- совместимость QR-команд `GS ( k`;
- поведение автостатуса.

## 4. Веб-интерфейс

Страница mobile-first, без внешних CDN, хранится в flash.

### Текст

- textarea с разметкой в стиле Adafruit_Thermal: `[setSize,L]`, `[boldOn]`,
  `[boldOff]`, `[justify,R]`, `[inverseOn]` и т. д.;
- теги выполняются последовательно, закрывающие не нужны;
- панель кнопок вставляет теги в позицию курсора;
- справка по всем тегам — встроенная и в `docs/TEXT.md`;
- отступ после печати (`ESC d`), подача строк/точек, табуляция;
- теги работают только в `.txt` и в поле «Текст»; `.md`/`.csv`/`.log`
  печатаются как обычный текст;
- Markdown-конвертер — отдельная вкладка, ESP32 его не разбирает.

### Markdown

- загрузка `.md` с устройства или с SD;
- свой парсер под subset: заголовки, bold, underline вместо курсива,
  strike, код, списки, цитаты, ссылки, таблицы, картинки;
- предпросмотр «как на чеке» и режим показа тегов;
- картинки: локальные `.bin/.raw` с SD или скачивание/конвертация в
  браузере с загрузкой на SD;
- сохранение результата как `.txt` на SD или перенос в поле «Текст».

### Фото

- выбор файла из галереи;
- canvas ровно 384 точки по ширине (48 мм);
- ограничение высоты 2000 строк (защита от случайной печати на метры);
- дизеринг: Флойд–Стейнберг, упорядоченный 4×4, порог;
- яркость, контраст, инверсия;
- предпросмотр в 1-битном виде;
- оценка времени печати при 9600 бод;
- отправка как multipart: 4 байта заголовка + упакованные строки.

### QR и штрихкоды

- QR: данные, размер модуля 1–8 (`GS ( k`);
- штрихкоды: CODE128, EAN13, EAN8, CODE39, ITF, CODABAR
  (`GS k`, `GS h`, `GS w`, `GS H`).

### Настройки

- плотность (heat time 1–255), сохранение в NVS;
- проверка принтера (бумага/статус);
- подача бумаги;
- тестовая страница;
- IP, SSID, RSSI, heap, uptime;
- перезагрузка;
- сброс Wi-Fi (возврат в `Thermal58-setup`).

### SD-карта

- состояние, объём, занято/свободно;
- загрузка `.bin`/`.raw`/`.prn` и текстовых `.txt`/`.md`/`.csv`/`.log`
  через multipart;
- список файлов с размерами, типом и размерами изображения;
- предпросмотр изображений в canvas и текста в `<pre>`;
- печать с карты, скачивание, удаление;
- переподключение карты без перезагрузки;
- сохранение текущего фото из вкладки «Фото» прямо на SD.

### API

- базовый URL и список эндпоинтов прямо на странице;
- примеры `curl`;
- CORS включён, чтобы API можно было вызывать с других устройств и из
  браузерных приложений.

## 6. Прошивка

### Файлы

```
src/esp32/config.h       пины, baud, лимиты
src/esp32/printer.h/.cpp UART, DTR, ESC/POS, CP1251/CP866, QR, штрихкоды
src/esp32/rich_text.h/.cpp разбор тегов текста, потоковая печать
src/esp32/sd_store.h/.cpp SD-карта: монтирование, список, чтение, печать
src/esp32/web_ui.h       HTML/CSS/JS в PROGMEM
src/esp32/main.cpp       Wi-Fi, HTTP, API, OTA
```

`src/thermal.cpp` — старый пример Uno + SD, не участвует в сборке ESP32
(`build_src_filter`).

### Передача в принтер

- `Serial2` 9600 8N1, RX=GPIO16, TX=GPIO17.
- DTR = GPIO4, `INPUT_PULLUP`, готовность = LOW.
- При старте прошивка проверяет DTR в течение 3 секунд. Если линия не
  подключена, flow control отключается и печать идёт с паузами. Если
  подключена, ожидание готовности — до 30 секунд, затем ошибка 503.
- Данные пишутся чанками по 64 байта с проверкой DTR.
- Каждое задание начинается с `ESC @`, `GS a 0x20` (DTR handshake),
  кодовой страницы CP1251 и настроек нагрева.

### Изображение

Формат тела `POST /api/bitmap` и файлов `.bin`/`.raw` на SD:

```
uint16 width   (LE)   1..384
uint16 height  (LE)   1..2000
byte   rows[height][(width+7)/8]   // MSB first, 1 = чёрный
```

Прошивка читает первые 4 байта, проверяет размеры, отправляет
`GS v 0 0 xL xH yL yH`, где `x = (width + 7) / 8`, и потоком пишет
строки. Файл целиком в RAM не хранится.

### SD-карта

- SPI/VSPI: SCK=GPIO18, MISO=GPIO19, MOSI=GPIO23, CS=GPIO21.
- FAT32, 4–32 ГБ; монтирование при старте, `POST /api/sd/remount` —
  переподключение без перезагрузки.
- `GET /api/sd/list` отдаёт объём, занято/свободно и файлы с типом
  (`image`, `raw`, `text`, `plain`) и размерами изображения.
- `POST /api/sd/upload` принимает multipart, проверяет заголовок
  `.bin`/`.raw`, отсутствие нулевых байтов в тексте, лимиты 512 КБ /
  64 КБ, имя санитизируется в ASCII с сохранением расширения
  (кириллица транслитерируется).
- `POST /api/sd/print` открывает файл и потоково передаёт его в принтер:
  `.bin`/`.raw` — как bitmap, `.prn` — как сырой ESC/POS, `.txt` — через
  `RichTextPrinter` с тегами, `.md`/`.csv`/`.log` — как обычный текст.
- `GET /api/sd/file` отдаёт файл для предпросмотра/скачивания
  (текст — `text/plain; charset=utf-8`); `POST /api/sd/delete` удаляет.
- В веб-интерфейсе есть вкладки «SD-карта», «Фото» и «Markdown».
- Отдельного хранилища шаблонов нет: часто печатаемый текст хранится
  обычным `.txt`-файлом на карте.

### Память

- HTML ~86 КБ в flash.
- RAM занята ~51 КБ; приложение ~1,11 МБ, partition 1,31 МБ — OTA
  работает (занято ~85%).
- Для JSON-запросов достаточно 16 КБ; текстовый файл на SD ограничен
  64 КБ и печатается потоково.

## 7. Wi-Fi, OTA, безопасность

### Первичная настройка

- При первом включении или после сброса ESP32 поднимает AP
  `Thermal58-setup` / `thermal58`.
- Через captive portal выбирается домашняя сеть, пароль сохраняется в NVS.
- Если сеть недоступна, снова поднимается AP (таймаут 180 с).

### OTA

- `ArduinoOTA`, имя `thermal`.
- `pio run -e esp32dev_ota -t upload` — обновление по Wi-Fi.
- Если `thermal.local` не резолвится, укажи IP:
  `pio run -e esp32dev_ota -t upload --upload-port 192.168.1.50`.
- OTA не защищён паролем; устройство должно быть только в доверенной сети.

### Безопасность

- API без авторизации: любой в сети может печатать.
- Не пробрасывать порт 80 наружу.
- Пароль на AP `Thermal58-setup` задан, но точка доступа временная.
- При необходимости later: `X-Api-Key`, Basic Auth на `/api/*`, отключение
  OTA.

## 9. Ограничения и риски

| Риск | Проверка / mitigation |
|---|---|
| DTR полярность/подключение | Проверить мультиметром; при отсутствии — таймаут и паузы |
| 5 В на GPIO ESP32 | TXS0108E на TX/RX/DTR (предпочтительно) или делитель 1k/2k на RX/DTR |
| Принтер не понимает CP1251 | Проверить страницу тестом `/api/test/codepage`; для T7-US рабочая — 6 (CP1251), запасная — 7 (CP866) |
| ESP32 не видит сеть 5 ГГц | ESP32 работает только в 2,4 ГГц; включить 2,4 ГГц на роутере |
| Роутер только WPA3 | ESP32 core 2.0.x рассчитан на WPA2; включить WPA2/WPA3 mixed |
| QR-команды не поддерживаются | Проверить тестовой печатью; fallback — растровый QR |
| 9600 бод медленно для фото | Ограничить высоту, уменьшить dither, попробовать 115200 |
| Просадка питания | Конденсатор 470–1000 мкФ, БП ≥ 2,5 А, провода 0,5–0,75 мм² |
| DTR не подключён | Прошивка определяет это при старте и печатает с паузами |
| Wi-Fi + OTA без пароля | Только доверенная сеть |
| Автостатус мусорит | Ответы принтера не пересылаются в HTTP; статус — по запросу |
| SD-модуль 5 В и MISO 5 В | Модуль с AMS1117-3.3 + 74LVC125A: питать 5 В, SPI напрямую (буфер на плате). Без буфера — TXS0108E на SPI |
| Карта exFAT/больше 32 ГБ | Форматировать в FAT32, использовать 4–32 ГБ |
| Плохой контакт/длинные провода SPI | Короткие провода, общий GND, 100 мкФ, `Переподключить карту` |
| Файл на SD повреждён | При загрузке проверяется заголовок и точный размер; при печати — тоже |
| Текстовый файл без SD | Вкладка SD показывает, что карты нет; печать недоступна |
| Текстовый файл слишком большой | Лимит 64 КБ; текст печатается потоково и не занимает всю RAM |
| Бинарный файл с расширением .txt | При загрузке проверяется отсутствие нулевых байтов |
| Теги идут по порядку | Закрывающих нет; неизвестный тег печатается literal; справка в UI и `TEXT.md` |
| `setCodePage` не 6/7 | Кириллица конвертируется только для CP1251 (6) / CP866 (7); другие страницы — ASCII |
| Долгая печать блокирует HTTP | Один принтер — одна очередь; на v1 это допустимо |
| Переполнение RAM при фото | Потоковая multipart-загрузка, файл не буферизуется |

## 11. Идеи развития

- Очередь печати и история заданий (в NVS/LittleFS).
- Прогресс печати в UI (сейчас запрос просто ждёт).
- Экспорт/импорт текстовых файлов и несколько пользователей.
- Печать PDF (рендер на клиенте через pdf.js, отправка растра).
- Приём изображений по URL (`/api/print?image=...`) с загрузкой на ESP32.
- Авторизация по токену.
- Telegram-бот как шлюз на ПК/RPi, если нужна печать извне.
- Поддержка 115200 и настройка принтера из UI.
- Несколько принтеров на одном ESP32 (второй UART).

6. ~~Какой SD-модуль: 3,3 В или 5 В с LDO/level shifter?~~ Решено:
