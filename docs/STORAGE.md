# Где что хранится

Карта хранилищ проекта: Wi-Fi, настройки принтера и файлы на SD.

## Сводная таблица

| Что | Где | Переживает перезагрузку | Переживает OTA/прошивку | Сбрасывается |
|---|---|---|---|---|
| Wi-Fi SSID + пароль | NVS ESP32, Wi-Fi-стек (через WiFiManager) | Да | Да | `POST /api/wifi/reset`, полное стирание flash |
| Плотность принтера `heat` | NVS ESP32, namespace `printer`, ключ `heat` | Да | Да | полное стирание flash/NVS; вручную — `POST /api/config` |
| Файлы `.bin/.raw/.prn` | SD-карта, корень | Да | Да | удаление через UI/API или форматирование карты |
| Текстовые `.txt/.md/.csv/.log` | SD-карта, корень | Да | Да | удаление через UI/API или форматирование карты |
| IP, SSID, RSSI, heap | оперативная память, вычисляется | — | — | перезагрузка |
| Пины, baud, лимиты | прошивка, `config.h` | — | — | пересборка/прошивка |

`localStorage` браузера **не используется**.

## 1. Wi-Fi: где лежит доступ

Пароль от домашней Wi-Fi-сети хранится **в NVS ESP32**, а не в коде и
не на SD.

Как это происходит:

1. При первом запуске WiFiManager поднимает AP `Thermal58-setup`
   (пароль `thermal58`).
2. Пользователь выбирает сеть и вводит пароль в captive portal.
3. WiFiManager вызывает `WiFi.persistent(true)` и `WiFi.begin(ssid, pass)`.
4. Wi-Fi-стек ESP32 сохраняет SSID/пароль в NVS — namespace
   `nvs.net80211` (внутренний раздел Wi-Fi-стека ESP-IDF).
5. После этого WiFiManager отключает `persistent`, чтобы служебные
   переключения режимов не затирали сохранённые данные.

Что важно:

- В коде **нет** домашнего SSID/пароля. В `config.h` только имя и пароль
  временной точки настройки: `Thermal58-setup` / `thermal58`.
- `POST /api/wifi/reset` вызывает `wm.resetSettings()` →
  `WiFi.disconnect(true, true)` и перезагружает ESP32. Wi-Fi-доступ
  стирается, поднимается `Thermal58-setup`. `heat` и файлы на SD
  остаются.
- `GET /api/status` показывает SSID, RSSI и IP, но **не** пароль.
- NVS не зашифрован (flash encryption/NVS encryption не включены).
  При физическом доступе к плате содержимое можно прочитать
  esptool/дампом. Для домашнего устройства это обычный компромисс;
  для улицы/офиса стоит включить flash encryption.

## 2. NVS контроллера: что хранит прошивка

Наша прошивка использует `Preferences` (обёртка над NVS) только для
плотности печати:

```text
namespace: "printer"
key:       "heat"
type:      uint8 (1..255)
default:   120
```

- Читается при старте в `printerLoadSettings()`.
- Пишется в `printerSetHeat()` при `POST /api/config`.
- Отдаётся в `GET /api/config` и `GET /api/status`.
- `POST /api/wifi/reset` его **не** трогает.
- Полное стирание flash (`pio run -t erase`, `esptool erase_flash`)
  удаляет NVS вместе с Wi-Fi; после этого `heat` снова 120.

Остальные настройки — **compile-time** в `config.h` и меняются только
пересборкой:

- `PRINTER_BAUD` (9600), пины UART/DTR/SD, `SD_SPI_HZ`;
- `HOSTNAME` (`thermal`), `WIFI_AP_NAME`, `WIFI_AP_PASS`;
- таймауты Wi-Fi, лимиты текста/QR/файлов, `DEFAULT_HEAT`.

## 3. Файлы на SD

Отдельного хранилища шаблонов нет. На SD лежат обычные файлы:

- `.bin` / `.raw` — 1-битные изображения с 4-байтным заголовком;
- `.prn` — сырой поток ESC/POS;
- `.txt` / `.md` / `.csv` / `.log` — текст в UTF-8, при печати
  разбираются теги форматирования.

API:

- `GET /api/sd/list` — список файлов с полем `kind`
  (`image`, `raw`, `text`);
- `POST /api/sd/upload` — multipart-загрузка, имя файла задаёт тип;
- `GET /api/sd/file?name=...` — просмотр/скачивание;
- `POST /api/sd/print` — печать файла с SD;
- `POST /api/sd/delete` — удаление;
- `POST /api/sd/remount` — переподключение карты.

Правила:

- Имена ASCII, до 48 символов с расширением; известное расширение
  сохраняется (`.txt` не превращается в `.bin`), кириллица
  транслитерируется.
- Лимиты: файл до 512 КБ, текстовый файл до 64 КБ, изображение
  384×2000 точек.
- Загрузка атомарная: сначала `*.tmp`, затем переименование в рабочее
  имя. При ошибке временный файл удаляется, старый не страдает.
- Текст печатается потоково, без загрузки файла целиком в RAM: теги
  могут стоять в любом месте, состояние форматирования сохраняется
  между строками и между блоками чтения.
- В тексте допустимы все теги из `docs/TEXT.md`. Файл печатается с
  авто-переводом строки в конце, если он не оканчивается на `\n`.
- Если SD-карты нет, список и кнопки работы с файлами недоступны.

## 4. localStorage браузера

Не используется. Ни текст, ни настройки принтера там не хранятся.

- Файлы — на SD.
- `heat` — в NVS.
- Wi-Fi — в NVS.
- Состояние UI (вкладка, положение курсора, яркость и т. п.) — только
  в памяти страницы и сбрасывается при перезагрузке/закрытии.

## 5. SD-карта

- Переживает перезагрузку, OTA и сброс Wi-Fi.
- Удаляется через UI/API или форматированием карты.
- Полное стирание flash ESP32 SD-карту не трогает.
- Имена ASCII; JPEG/PNG на карту не кладутся (конвертируются в
  браузере в `.bin`). Текстовые файлы загружаются как есть.
- Временные `*.tmp` существуют только на время записи и удаляются при
  ошибке.

## 6. Матрица сбросов

| Действие | Wi-Fi в NVS | `heat` в NVS | Файлы на SD |
|---|---|---|---|
| Перезагрузка / `POST /api/restart` | сохраняется | сохраняется | сохраняются |
| OTA / `pio run -t upload` | сохраняется | сохраняется | сохраняются |
| `POST /api/wifi/reset` | **стирается** | сохраняется | сохраняются |
| `pio run -t erase` / `esptool erase_flash` | **стирается** | **стирается** | сохраняются |
| Форматирование SD | сохраняется | сохраняется | **стираются** |
| Удаление файла в UI/API | сохраняется | сохраняется | **удаляется один** |
| `POST /api/config` с новым `heat` | сохраняется | **меняется** | сохраняются |

## 7. Практические выводы

- Пароль Wi-Fi нигде в репозитории не лежит — его вводят один раз через
  `Thermal58-setup`.
- Чтобы сбросить только Wi-Fi — «Настройки → Сбросить Wi-Fi» или
  `POST /api/wifi/reset`.
- Чтобы вернуть плотность по умолчанию — `POST /api/config` с
  `{"heat":120}`.
- Текстовые файлы общие для всех устройств, потому что лежат на SD.
  Резервная копия — скопировать файлы с карты или скачать их через
  `/api/sd/file`.
- Если нужен полный сброс «как из коробки» — стереть flash и залить
  прошивку заново; SD-карту при этом можно оставить.
