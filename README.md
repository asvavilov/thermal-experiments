# thermal — Wi-Fi принтер на ESP32

ESP32 подключается к домашней Wi-Fi-сети, поднимает HTTP API и
веб-интерфейс и печатает на 58-мм термопринтер **GZQIANJI T7-US** через
UART. Печатать можно с любого устройства в сети: Android, Windows, Linux,
планшета или скрипта — достаточно браузера или HTTP-запроса.

## Возможности

- **Текст:** размер S/M/L, жирный, подчёркивание, выравнивание, отступ,
  русский текст (UTF-8 → CP1251), а также последовательная разметка
  тегами в стиле Adafruit_Thermal: `[setSize,L]`, `[boldOn]`, `[justify,R]`,
  `[inverseOn]` и другие.
- **Фото:** выбор из галереи, предпросмотр, дизеринг (Флойд–Стейнберг,
  упорядоченный, порог), яркость, контраст, инверсия, ширина 384 точки.
- **QR-коды и штрихкоды:** CODE128, CODE93, EAN13, EAN8, CODE39, ITF,
  CODABAR, UPC-A, UPC-E.
- **SD-карта:** загрузка готовых `.bin`/`.raw`, исходных картинок
  `.png`/`.jpg`/`.jpeg`/`.gif`/`.bmp`/`.webp`, сырого ESC/POS `.prn` и
  текстовых файлов `.txt`/`.md`/`.csv`/`.log`; исходники хранятся как
  есть и конвертируются в `.bin` уже во вкладке «Фото»; список,
  предпросмотр текста и изображений, скачивание и удаление. «Открыть» не
  печатает файл сразу, а переносит его в нужное место («Текст» с выбором
  формата или «Фото»), где содержимое можно поправить и отправить на
  печать. Сохранённый `.bin` открывается в «Фото», и к нему снова
  применяются яркость, контраст и инверсия (файл уже 1-битный, поэтому
  дизеринг не добавит полутонов). Фото из браузера конвертируется в
  1-битный `.bin` и сохраняется на карту.
- **Три формата в поле «Текст»:** «Текст с форматированием» (теги
  ESC/POS), «Markdown» и «Текст без форматирования». Для Markdown есть
  конвертация в теги, предпросмотр и печать; ESP32 сам Markdown не
  разбирает. Результат можно сохранить как `.txt` на SD.
- **Теги форматирования** работают только в `.txt` и в режиме «Текст с
  форматированием»; `.md`, `.csv`, `.log` и режим без форматирования
  печатаются как есть.
- **Настройки:** плотность печати, тестовая страница, подача бумаги,
  статус принтера, сброс Wi-Fi, перезагрузка.
- **REST API** с CORS — интеграция с Home Assistant, скриптами, Android.
- **mDNS** `http://thermal.local` и работа по IP.
- **OTA-обновление** прошивки по Wi-Fi.
- **Первичная настройка Wi-Fi** через точку доступа `Thermal58-setup`
  (captive portal), настройки сохраняются в NVS.

## Железо

- Принтер GZQIANJI T7-US: 58 мм, 384 точки, ESC/POS, питание 5–9 В,
  пиковый ток ~2 А.
- ESP32-WROOM-32 (Classic BT не используется, нужен только Wi-Fi).
- БП 12 В 2 А + MP1584EN на 7,4 В для принтера; ESP32 — от USB или
  отдельного 5 В buck-преобразователя.
- TXS0108E для линий 5 В ↔ 3,3 В (предпочтительно) или резисторы
  1 кОм / 2 кОм; конденсатор 470–1000 мкФ рядом с J1.
- SD-модуль: SPI (SCK 18, MISO 19, MOSI 23, CS 21). Модуль с AMS1117-3.3
  и 74LVC125A питается от 5 В, сигналы — напрямую, без TXS0108E (см.
  `docs/HARDWARE.md`, раздел 5).

Подробная распиновка и питание — в [`docs/HARDWARE.md`](docs/HARDWARE.md).

## Быстрый старт

1. Собрать и залить прошивку:

   ```powershell
   pio run -e esp32dev -t upload
   ```

   Если `pio` не в PATH, используй
   `%USERPROFILE%\.platformio\penv\Scripts\pio.exe`.
   Если в системе несколько COM-портов (например, Bluetooth), укажи
   порт явно: `pio run -e esp32dev -t upload --upload-port COM7`
   (список — `pio device list`).

2. Первый запуск: ESP32 поднимет точку доступа **Thermal58-setup**
   (пароль `thermal58`). Подключиться к ней с телефона/ПК, выбрать
   домашнюю сеть и ввести пароль. Настройки сохранятся.

   > ESP32-WROOM-32 работает только в **2,4 ГГц**. Сеть должна быть
   > 2,4 ГГц (или двухдиапазонной с включённым 2,4 ГГц) и WPA2;
   > WPA3-only может не подойти.

3. Открыть `http://thermal.local` или IP-адрес из Serial Monitor
   (115200 бод). Если mDNS не работает на Android — используй IP.

4. В веб-интерфейсе: **Настройки → Проверить принтер**, затем
   **Тестовая страница**. Там же — «Самотест принтера» (`DC2 T`): плата
   печатает свою конфигурацию (baudrate, heat, версия прошивки).

## Обновление по Wi-Fi

```powershell
pio run -e esp32dev_ota -t upload
```

После заливки сверь номер в `GET /api/status` с `FW_VERSION` из
`src/esp32/config.h`. Если номер не изменился — устройство откатилось на
прежнюю прошивку (в `otadata` образ помечается как aborted); в этом случае
прошей по USB: `pio run -e esp32dev -t upload --upload-port COM10`.

## Если сборка падает с `No module named 'intelhex'`

Это известная проблема окружения PlatformIO + esptool. Один раз выполнить:

```powershell
& "$env:USERPROFILE\.platformio\penv\Scripts\python.exe" -m pip install intelhex
```

## Структура проекта

```
src/esp32/main.cpp       точка входа, Wi-Fi, HTTP API, OTA
src/esp32/printer.cpp    UART, DTR, ESC/POS, CP1251/CP866, QR, штрихкоды
src/esp32/rich_text.cpp  разбор тегов форматирования текста
src/esp32/sd_store.cpp   SD-карта: список, чтение, печать, удаление
src/esp32/web_ui.h       веб-интерфейс (HTML/CSS/JS в flash)
src/esp32/config.h       пины, baud, лимиты
src/thermal.cpp          старый пример Uno + SD (не используется)
docs/                    документация
```

## Что не используется

- USB-переходник и Bluetooth-мост — не входят в текущую архитектуру.
  USB-порт принтера (J3) можно использовать только для сервисной
  настройки принтера, если понадобится.
- Старый пример `src/thermal.cpp` (Arduino Uno + SD-карта) оставлен для
  истории; после проверки Wi-Fi-версии его можно удалить.
